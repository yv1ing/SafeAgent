# 快速上手

[English](getting-started.md)

本指南从一份全新的代码副本开始，把网关跑起来，配置一个供应商和一条路由，最后让 Agent 发一次可以在控制台里查看的请求。

## 环境准备

- Go 1.27.4
- Node.js 22 或更新版本
- GNU Make
- 一个已经创建好的 PostgreSQL 17 数据库

SafeAgent 首次启动时建表，但不会创建数据库本身。先安装锁定版本的后端与前端依赖：

```sh
make deps
```

## 配置与启动

复制示例配置，填上两个必填项：

```sh
cp config.example.toml config.toml
```

```toml
listen = "127.0.0.1:8080"
database_url = "postgres://safeagent:change-me@localhost:5432/safeagent?sslmode=disable"
instance_key = "<openssl rand -base64 32 的输出>"
secure_cookies = false
```

实例密钥为必填项，必须是 32 字节的标准 base64。它用于认证审计链、加密保存的凭据，且不会写入数据库。请妥善保存：丢失后，已保存的渠道密钥和现有审计链都无法读取。其余配置项都有默认值。下面两项需要按部署方式调整：

- `secure_cookies` 默认为 `true`。只有在本机回环地址上用明文 HTTP 访问控制台时才设为 `false`；其他部署应使用 HTTPS 并保持 `true`，否则浏览器会丢弃 Secure Cookie。
- `sslmode=disable` 只适用于本地数据库，远程数据库应启用 TLS。

配置文件里出现无法识别的键会直接启动失败，拼写错误不会被悄悄忽略。

构建并运行：

```sh
make build
build/bin/safeagent -config config.toml serve
```

构建产出的是内嵌控制台的单个二进制。`make run` 会直接从源码启动服务，但控制台由 `web/dist` 提供，因此第一次使用前至少要执行一次 `make build`。`make dev` 会同时启动后端和控制台开发服务器。

首次连接空数据库时，进程会建好表结构，并打印一次管理员账号与密码：

```text
Initial administrator: admin / <password>
```

后续启动不会再次输出。密码丢失时，可由其他管理员重置，或重建数据库。同一个进程提供控制台（`/console/`）、网关（`/v1/` 与 `/v1beta/`）和健康检查（`/health`）。

## 登录并创建项目

打开 <http://127.0.0.1:8080/console/> 登录。首次登录必须修改密码，新密码长度 14 到 72 字节，且同时包含小写字母、大写字母和数字。控制台默认进入监控页，汇总当前账号可见的所有项目。

创建一个项目，填写名称即可，其他默认值可以稍后调整。新项目会启用常用脱敏检测器，带一份空的策略文档，主调用保留 30 天，辅助调用保留 3 天。

进入项目后，侧边栏切换为该项目的页面。项目成员可以管理路由、非阻断类脱敏规则和 Agent 密钥；管理员额外管理供应商、渠道、模型、用户、成员、策略编辑与恢复、阻断类脱敏规则、决策模型、保留期和限额。配置变更会写入操作记录：全局日志列出全部变更，项目操作记录页面列出发生在该项目内的变更。

## 连接供应商

供应商、渠道和模型是全局的，路由属于项目。供应商描述协议端点与能力；渠道把供应商绑定到基础地址、凭据和限额；目录中的模型记录上游模型名、类型以及每百万 Token 的价格。

在“管理”下的供应商页面，内置供应商已经以可编辑记录的形式存在。接入一个新供应商时，选择内置供应商，或添加一个自定义供应商并填写基础地址，录入上游 API 密钥，执行模型发现并勾选端点返回的模型。向导会在一个事务里创建供应商、渠道、凭据和导入的模型；密钥使用实例密钥加密，保存后只显示末尾几位。

如果端点位于内网地址，需要在该渠道上允许私有网络。每个渠道可以单独设置超时、输出上限和需要转发的请求头；同一个供应商也可以由多个渠道承担，使用不同密钥。

模型可以在模型页面补充或修正。模型归属于供应商，记录上游名称、类型（生成、嵌入或审核）、价格和启用状态。可用格式由供应商端点与模型类型推导，不需要单独维护格式列表。

## 创建路由

路由把对外的模型名映射到项目内的一组目标，在项目的“模型路由”页面创建：

- 名称就是 Agent 在 `model` 字段里发送的模型名；别名可以让旧名称或备选名称继续可用；
- 每个目标是渠道加目录模型，并带有优先级、权重，以及可选的格式与输出上限；
- 同一条路由的所有目标必须使用相同类型的模型；
- 优先级数字越小越先尝试，优先级相同时按权重随机选择。

渠道和模型都支持客户端格式时，路由优先使用客户端格式，否则使用第一个可用格式。如果项目里 Agent 的后台调用会使用未配置的模型名，可以设置一条默认路由让这些调用兜底；调用详情会把这类调用标记为兜底解析。

## 签发 Agent 密钥

在项目的“Agent 密钥”页面签发密钥。完整密钥只显示一次，请在签发时复制。密钥带有标签、可选的请求速率与并发限额，以及策略规则可以读取的角色和信任级别。只有管理员可以设置非默认角色或信任级别。

## 让 Agent 接入网关

把网关地址和密钥交给 Agent，模型名使用路由名称。上游模型名留在目录里，不会暴露给客户端。

| Agent 协议         | 基础地址                   | 密钥位置                            |
| ------------------ | -------------------------- | ----------------------------------- |
| Chat Completions   | `http://127.0.0.1:8080/v1` | `Authorization: Bearer <key>`       |
| Responses          | `http://127.0.0.1:8080/v1` | `Authorization: Bearer <key>`       |
| Anthropic Messages | `http://127.0.0.1:8080`    | `x-api-key: <key>`                  |
| Gemini             | `http://127.0.0.1:8080`    | `x-goog-api-key: <key>`，或 `?key=` |

多数客户端都支持自定义基础地址，因此 Claude Code、Codex、Gemini CLI 或普通 HTTP 客户端都能接到同一个入口。可选的 `X-SafeAgent-Session` 请求头把同一 Agent 密钥下的调用归入同一会话，身份仍然来自密钥。客户端支持时应优先使用 `previous_response_id`。

发起第一个请求：

```sh
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer <agent-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"public-model","messages":[{"role":"user","content":"hello"}]}'
```

## 在控制台观察

请求会出现在项目的“调用”页面。每行带有通道、操作、用途和结果标记，主调用、后台调用和辅助协议调用一眼就能区分。辅助调用默认隐藏，打开开关后才显示；侧调用可以按通道折叠。

打开一个会话可以看到行为轨迹：默认是流程图，也可以切换到树形或平铺视图，三种视图共用同一批节点。选中节点可以查看对应的调用、条目或发现，沿审计事件向前或向后单步回放，并打开脱敏小结查看每个不同的脱敏值及其出现位置。会话头部会给出脱敏值数量与命中次数。

项目的“风险”页面按风险来源、失败模式、伤害和严重程度汇总发现，列出高频发现代码与 Agent 密钥，并链接最近的高风险调用；展开某个密钥可以看到它的数据流。监控页给出跨项目的流量、失败和近期高风险调用。策略与脱敏页面分别维护有序规则表和检测规则，保存时校验并立即生效。

想端到端确认脱敏效果，可以发送一段包含邮箱地址的提示词。上游收到的请求里是 `[EMAIL_…]` 这样的占位符，客户端收到的回复里是原始邮箱，而这次调用会显示一个脱敏值。

## 容器部署

构建镜像并挂载配置：

```sh
docker build -t safeagent .
docker run -d --name safeagent -p 127.0.0.1:8080:8080 \
  -v "$PWD/config.toml:/app/config.toml:ro" safeagent
```

在容器里，服务需要监听所有网卡，并通过容器内可解析的主机名访问数据库：

```toml
listen = "0.0.0.0:8080"
database_url = "postgres://safeagent:change-me@db-host:5432/safeagent?sslmode=require"
instance_key = "<openssl rand -base64 32 的输出>"
secure_cookies = true
```

启用 `secure_cookies = true` 后，控制台需要 HTTPS。应通过终止 TLS 的反向代理对外提供服务，并把 `public_origin` 设为浏览器实际访问的地址，例如 `https://safeagent.example.com`。如果反向代理直接连接应用，把代理的地址或 CIDR 加入 `trusted_proxies`，控制台才能读到客户端地址用于登录限流。运行镜像不含 shell 和 HTTP 客户端，请从外部检查 `/health`。

## 常见问题

| 提示或现象                                          | 处理方式                                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `database_url is required`                          | 在配置文件中填写该项，或确认进程读取的是已编辑的文件。                                     |
| `instance_key is required`                          | 填写 32 字节 base64 的 `instance_key`。                                                    |
| 启动时报未知配置键                                  | 某个键拼写有误，按错误信息中的名称改正。                                                   |
| `the database schema does not match this build`     | 数据库来自另一个构建。重建数据库，系统不提供迁移。                                         |
| `the database has tables but no schema fingerprint` | 数据库由其他工具创建，或上次启动只完成了一部分。请重建数据库。                             |
| `another SafeAgent instance owns this database`     | 一个数据库只能由一个实例使用，请停止另一个进程。                                           |
| 控制台返回 404                                      | 控制台前端尚未构建，运行 `make build`。                                                    |
| 登录成功但刷新后被登出                              | 部署在 HTTP 下却设置了 `secure_cookies = true`。使用 HTTPS，或在回环地址上将其设为 false。 |
| 反向代理后控制台写操作失败                          | 将 `public_origin` 设为用户在浏览器中打开的地址。                                          |
| 控制台中供应商或模型出现告警                        | 某条路由引用了已删除或已停用的对象。恢复对象，或移除受影响的目标。                         |
| 请求返回 403，或流以工具调用错误结束                | 命中了阻断类脱敏规则、策略规则或决策模型的否决。调用记录会写明来源，异步诊断仍会运行。     |
| 后台调用成功但会话里找不到                          | 侧调用与辅助调用按设计折叠或隐藏，打开对应的通道筛选即可。                                 |
