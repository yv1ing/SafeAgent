# 同类方案

[English](landscape.md)

AxonHub、magpie 与 Sub2API 同样在 Agent 和模型服务之间提供网关，但各自的优化目标不同：供应商覆盖、本机 Agent 配置，以及订阅配额。将 SafeAgent 与它们并列，更便于说明它的定位，以及它有意不承担哪些职责。

## 比较依据

这里的比较依据三个项目公开的文档与 README，没有运行基准测试；描述的是各家大致的做法，不针对某个具体版本。它们方向相近，但不构成排名。功能、许可证和内部实现均变化较快，需要依赖某个细节时，请直接查阅项目本身。

## SafeAgent

SafeAgent 是面向 Agent 行为的自托管安全网关。它支持 Chat Completions、Responses、Anthropic Messages 与 Gemini，通过一套规范模型双向转换，在请求方向脱敏、响应方向还原，并将每次放行的调用写入签名审计链。

SafeAgent 以一次调用为分析单位，调用链构成会话。全局的模型供给（供应商、渠道、模型）与项目内的路由、目标和别名分开管理。网关、控制台与诊断共享同一份调用记录，运维看到的结论与当时执行的判断一致。

## AxonHub

AxonHub 是多供应商 AI 网关与开发平台：用一套接口接入大量模型，并提供路由、负载均衡、成本统计、RBAC 和请求追踪。其供应商目录规模较大，包含各种厂商变体和 OAuth 渠道。

AxonHub 以 trace 或 thread 为分析单位，分为请求层和执行层。渠道、模型与关联规则分开管理，一个模型可以连接多个渠道，路由策略单独编辑。请求经过一层以 OpenAI Chat Completions 为模板的统一中间表示，非 OpenAI 语义置于附加字段中；同格式流量可以按原始字节透传。关系型 schema 由 ORM 管理，配置变更通过管理界面完成。

## magpie

magpie 是面向多个 Agent CLI 的本机网关与配置协调器。它为 Claude Code、Codex 这类工具提供统一地址，归集上游账号，并代为写出客户端配置。

magpie 以一次网关调用为分析单位，按客户端会话分组。配置围绕供应商、账号、组和路由组织。协议转换覆盖四种格式，改写 Agent 配置文件是它的核心能力。它按客户端声明的类型、归一化后的用途以及调用方是 Agent 还是网关自身来区分调用；每个脱敏值对应一个固定占位符，占位符即其标识。状态保存在本地文件中，不存入共享数据库。

## Sub2API

Sub2API 是订阅配额分发与转售平台。它归集上游账号，并按用户、组和模型管理配额、计费、限流与调度。

Sub2API 以单次请求为分析单位，用量与运营错误分别记账。配置围绕账号、组、渠道与组合组组织。协议转换以成对转换为主，部分路径以 Responses 作为枢纽。持久状态存放在关系型数据库中，并配有一层缓存。

## 横向对照

| 维度     | SafeAgent                                        | AxonHub                              | magpie                            | Sub2API                      |
| -------- | ------------------------------------------------ | ------------------------------------ | --------------------------------- | ---------------------------- |
| 定位     | Agent 行为安全网关                               | 多供应商 AI 网关与平台               | 本机多 Agent CLI 网关与配置协调器 | 订阅配额、计费与中转         |
| 分析粒度 | 一次调用，调用链组成会话                         | trace 或 thread，分请求层与执行层    | 一次网关调用，按客户端会话分组    | 单次请求，用量与错误分别记账 |
| 配置结构 | 供应商 → 渠道 → 模型的供给图，加上项目路由与别名 | 渠道与模型，加上关联规则             | 供应商、账号、组与路由            | 账号、组、渠道与组合组       |
| 协议策略 | 四格式规范模型，同格式原始透传                   | 以 OpenAI 为模板的中间表示，成对转换 | 四格式互转，改写 Agent 配置       | 成对转换，Responses 作枢纽   |
| 存储     | PostgreSQL，配置与签名审计链                     | 关系型 schema，由 ORM 管理           | 本地文件                          | 关系型数据库加缓存层         |

## 借鉴的做法

- **来自 AxonHub：** 供给配置与路由策略分层，请求和每次尝试均有记录，以及从类型化节点重建轨迹并支持多种视图的做法。以 OpenAI 为模板的中间表示与针对具体客户端的处理，仍是 AxonHub 的选择。
- **来自 magpie：** 按端点操作、声明用途与通道对调用分类；用固定占位符标识脱敏值，同一个值重复出现也仅记录一条。
- **来自 Sub2API：** 带影响检查的软删除生命周期，以及用量与错误分别记账的做法。

SafeAgent 的贡献正是将这些做法组合起来：转换、在线策略与审计置于同一条调用路径上，供应商范围比通用网关窄，策略在工具边界上执行，而非仅做事后流量检查。
