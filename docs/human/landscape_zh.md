# 同类方案

[English](landscape.md)

这份文档把 SafeAgent 放在两类相邻系统之间：一类解决“Agent 使用多种协议、上游只认一种协议”的网关问题，另一类解决“Agent 调用了不该调用的工具”的护栏问题。前者以 AxonHub 和 Sub2API 为代表，后者以 AgentGuard 和 AgentDoG 为代表。

两类系统的优化目标不同，功能数量无法直接比较；值得比较的是各自把复杂度放在哪里、让渡了什么。

## 方法与口径

本文只使用可核对的一手材料：参考项目的代码快照与 README，以及论文的 arXiv 版本。核对日期为 2026-11-21。

- AxonHub 使用本地快照 `axonhub-1.0.0-rc.4`。该快照内部的版本标记并不一致（构建版本、CHANGELOG 与目录名不同），本文因此用目录名作为快照标识。
- Sub2API 使用本地快照 `sub2api-0.2.24`，其 `VERSION` 文件为 `0.2.23`；本文同样把目录名当作快照标识。
- AgentGuard 引用 arXiv:2605.28071v1（2026-05-27）。
- AgentDoG 引用 arXiv:2601.18491v2（2026-04-23）。

本文描述机制与取舍。论文的基准数字不作为证据，论文主张也不视为经过独立验证的结论。参考项目会继续演进，具体能力以对应版本的代码为准。

## AxonHub

AxonHub 定位为多提供商 AI 网关与开发平台：用一个统一接口接入多家模型，附带路由、负载均衡、成本统计、RBAC 和请求追踪。

它同样使用统一中间表示，IR 以 OpenAI Chat Completions 为形状，非 OpenAI 语义通过附加字段承载。请求路径是一次入站转换加一次出站转换；同格式且无需改写时可以原始透传。流式转换按事件进行，支持 SSE、WebSocket 与 Gemini 数组帧。

提供商目录规模较大，包含大量厂商变体和 OAuth 渠道。路由支持自适应、故障转移、熔断和轮询等策略。

安全方面，AxonHub 覆盖了网关层面的基础防护：API Key、项目与角色、配额、IP 允许列表、敏感头遮蔽、输入正则保护，以及可选的 Claude Code 工具调用审查。提示保护以输入文本的正则替换或拒绝为主。通用工具级策略、人工审批、输出侧检查与签名审计链不在其范围内。

其设计重心是提供商覆盖、路由策略与运维功能，Agent 行为边界不在其中。

许可证方面，根目录为 Apache-2.0，`llm/` 目录为 LGPL-3.0，派生工作需要注意目录级差异。

## Sub2API

Sub2API 定位为订阅配额分发与转售平台：把多个上游账号组织成池，按用户、分组和模型做配额、计费、限流和调度。

协议转换以成对转换为主，并用 Responses 作为部分路径的中枢；代码中同时存在直接桥接和链式路径，后者避免部分组合经过两次转换。所有路径并未统一到一个规范模型。

流式处理采用手写状态机，严格的字段序列化满足 Codex、Grok 等客户端对字段存在性的要求。用量归一化能够区分不同提供商的缓存字段与 TTL 桶。

安全方面，Sub2API 提供输入内容审核和可选的 prompt audit，管理面有 append-only 审计日志，账号调度与并发控制较为完整。工具调用门禁、人工审批、输出 DLP 和 Agent 动作审计不在其范围内。

上游 URL 校验默认较宽松，账号凭据与用户 API Key 在应用层未见统一加密。

其设计重心是账号池、计费和运营，Agent 安全不在其中。

许可证为 LGPL-3.0-or-later。

## AgentGuard

AgentGuard 是一篇短论文提出的客户端/服务器访问控制框架。客户端挂在 Agent 框架与工具之间，把主体、工具、参数、目标和会话历史发给中央策略服务；服务端可以用规则、LLM 辅助判断或人工复核，返回允许、拒绝或转人工。

它采用属性式访问控制的词汇，强调单工具和跨工具链策略，并提供可视化策略与审计界面。论文没有给出量化评测，也没有形式化威胁模型；仓库 README 还描述了论文未展开的插件与集成能力。

许可证存在差异：论文称 MIT，仓库声明 GPL-3.0。

SafeAgent 借鉴运行时属性和“策略可以覆盖工具链”的思路；具体实现保留在 AgentGuard。

## AgentDoG

AgentDoG 是一篇面向轨迹的诊断型护栏论文。它把风险拆成三个正交维度：风险来源（从哪里进入）、失败模式（Agent 如何失败）、现实危害（造成什么后果），并用微调的 guard model 对整条轨迹做安全判定和细粒度标签。

论文还提出步级与句级的归因方法，以及一个轨迹级基准。

它的输入是文本轨迹，评测依赖论文构建的基准；论文本身也指出细粒度失败模式判断仍较困难。模型与基准以 Apache-2.0 发布，但论文与仓库是独立产物，版本与数字需要分别核对。

SafeAgent 借鉴分类法和“轨迹是分析单位”的思路；训练模型和基准保留在 AgentDoG。

## 维度对比

| 维度       | AxonHub                   | Sub2API                       | AgentGuard               | AgentDoG         | SafeAgent                                                        |
| ---------- | ------------------------- | ----------------------------- | ------------------------ | ---------------- | ---------------------------------------------------------------- |
| 主要目标   | 多提供商网关与开发平台    | 订阅配额分发与计费            | 工具调用访问控制         | 轨迹级安全诊断   | Agent 行为安全网关                                               |
| 转换模型   | OpenAI 形状统一 IR        | 成对转换 + Responses 中枢     | 不涉及                   | 不涉及           | item/part 规范模型 + 能力描述                                    |
| 流式处理   | 事件级转换 + 原始透传     | 手写成对状态机                | 不涉及                   | 不涉及           | 提交边界 + 工具缓冲 + 原始透传                                   |
| 工具边界   | 可选 Claude Code 审查器   | 无工具级门禁                  | 客户端 hook + 服务端策略 | 轨迹级判定       | 请求、工具结果、工具调用、响应四个检查点，另有可选的流式预审窗口 |
| 策略方式   | 网关配置 + 输入正则       | 网关配置 + 输入审核           | 属性规则 / LLM / 人工    | 微调 guard model | 类型化规则，四阶段，决策模型仅否决                               |
| 审计与证据 | 请求/尝试血缘             | 管理面 append-only + 用量日志 | 规则命中与审计元数据     | 步级/句级归因    | 签名事件链 + 时间线 + 来源到去向关系                             |
| 部署形态   | Go 服务 + 数据库/缓存选项 | Go + PostgreSQL + Redis       | 客户端 SDK + 服务端      | 模型推理服务     | 单 Go 进程 + PostgreSQL                                          |

这张表比较设计重心，不进行能力排名。AxonHub 的提供商覆盖和路由策略更广；Sub2API 的账号池、计费和运营能力更完整；AgentGuard 把策略放在 Agent 运行时旁边；AgentDoG 的模型诊断能力来自训练数据，SafeAgent 不试图复制。

SafeAgent 把协议转换与行为边界放在同一个进程、同一份观察模型上，以较窄的协议范围换取在线拦截与审计的一致性。

## SafeAgent 借鉴了什么

- **来自 AxonHub**：提供商目录与端点预设、同格式原始透传、请求与尝试血缘的可见性。OpenAI 形状 IR 与特定客户端审查器保留在 AxonHub。
- **来自 Sub2API**：严格的字段与终止事件处理、用量归一化、管理面审计不可变的思路。账号池、计费与成对转换保留在 Sub2API。
- **来自 AgentGuard**：主体、工具、参数、目标和历史这组运行时属性，以及覆盖工具链的策略视角。客户端 SDK、DSL 与人工复核队列保留在 AgentGuard。
- **来自 AgentDoG**：8/14/10 分类法、轨迹作为分析单位、诊断与判定分离。训练模型与基准保留在 AgentDoG，SafeAgent 不声称复现。

## 声明边界

- 本文不声称 SafeAgent 在检测准确率、吞吐或覆盖率上优于任何参考项目；没有进行同条件基准。
- 本文不声称任何设计由 SafeAgent 首次提出。统一 IR、网关级策略、轨迹分类法都已有先例，SafeAgent 的贡献在于工程组合与边界选择。
- 外部事实以核对日期的版本为准；许可证可能随仓库变化，派生工作应重新核对。
- 参考项目的“没有某能力”指在该快照的代码与文档中未发现，不表示未来版本不会提供。
