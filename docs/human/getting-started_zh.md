# 快速上手

[English](getting-started.md)

本指南从一份新的代码副本开始，启动网关，配置一个供应商和一条路由，最后使 Agent 发出一次可以在控制台查看的请求。

## 环境准备

- Go 1.27.4
- Node.js 22 或更新版本
- GNU Make
- 一个已经创建好的 PostgreSQL 17 数据库

SafeAgent 首次启动时会初始化数据库，但不会创建数据库本身。先安装依赖：

```sh
make deps
```

## 配置与启动

复制示例配置，填写两个必填项：

```sh
cp config.example.toml config.toml
```

```toml
listen = "127.0.0.1:8080"
database_url = "postgres://safeagent:change-me@localhost:5432/safeagent?sslmode=disable"
instance_key = "<openssl rand -base64 32 的输出>"
secure_cookies = false
```

实例密钥必须是 32 字节的标准 base64。它用于签名轨迹事件链、加密渠道凭据，并且不会写入数据库，请妥善保存；丢失后，已保存的渠道密钥和现有轨迹链都无法恢复。其余配置项都有默认值，下面两项需要按部署方式调整：

- `secure_cookies` 默认为 `true`。只有在本机回环地址上用明文 HTTP 访问控制台时才设为 `false`；其他部署应使用 HTTPS 并保持 `true`，否则浏览器会丢弃 Secure Cookie。
- `sslmode=disable` 只适用于本地数据库，远程数据库应启用 TLS。

配置文件中出现无法识别的键会直接启动失败，拼写错误不会被静默忽略。

构建并运行：

```sh
make build
build/bin/safeagent -config config.toml serve
```

构建产物是内嵌控制台的单个二进制。`make run` 直接从源码启动服务，但控制台由 `web/dist` 提供，因此首次使用前至少需执行一次 `make build`。`make dev` 会同时启动后端和控制台开发服务器。

首次连接空数据库时，服务会完成初始化，并打印一次管理员账号与密码：

```text
Initial administrator: admin / <password>
```

后续启动不会再次输出。密码丢失时，可由其他管理员重置，或重建数据库。控制台位于 `/console/`，网关位于 `/v1/` 与 `/v1beta/`，健康检查位于 `/health`。

## 登录并创建项目

打开 <http://127.0.0.1:8080/console/> 登录。首次登录必须修改密码，新密码长度为 14 到 72 字节，且同时包含小写字母、大写字母和数字。控制台默认进入监控页，汇总该账号可见的全部项目。

创建一个项目，填写名称即可，其他默认值可以稍后调整。新项目会启用常用脱敏检测器，策略文档为空，主调用与侧调用保留 30 天，辅助调用保留 3 天。

进入项目后，侧边栏切换为该项目的页面。项目成员可以管理路由、非阻断类脱敏规则和 Agent 密钥；管理员还可以管理供应商、渠道、模型、用户、成员、策略编辑与恢复、阻断类脱敏规则、决策模型、保留期和限额。配置变更会写入操作记录：全局日志列出全部变更，项目的操作记录页面列出发生在该项目内的变更。

## 连接供应商

供应商、渠道和模型是全局的，路由属于项目。供应商描述协议端点与能力；渠道为供应商配置基础地址、凭据和限额；目录中的模型记录上游模型名、类型以及每百万 Token 的价格。

“管理”下的供应商页面已经预置了内置供应商，可以直接编辑。接入新供应商时，选择内置供应商，或添加一个自定义供应商并填写基础地址，录入上游 API 密钥，运行模型发现并勾选端点返回的模型。向导会一次性创建供应商、渠道、凭据和导入的模型；保存时用实例密钥加密，之后只显示末尾几位。

如果端点位于私有网络中，需要在该渠道上允许访问私有网络。每个渠道可以单独设置超时、输出上限和需要转发的请求头；同一个供应商也可以配置多个渠道，各自使用不同密钥。

模型可以在模型页面补充或修正。模型归属于供应商，记录上游名称、类型（生成、嵌入或审核）、价格和启用状态。可用格式由供应商端点和模型类型决定，不需要单独维护格式列表。

## 创建路由

路由将对外模型名映射到项目内的一组目标，在项目的“模型路由”页面创建：

- 名称即 Agent 在 `model` 字段中发送的模型名；别名可使旧名称或备选名称继续可用；
- 每个目标由渠道和目录模型组成，并带有优先级、权重，以及可选的格式与输出上限；
- 同一条路由的所有目标必须使用相同类型的模型；
- 优先级数字越小，尝试顺序越靠前；优先级相同时按权重随机选择。

渠道和模型支持客户端格式时，路由优先使用客户端格式，否则使用第一个可用格式。如果项目中 Agent 的后台调用使用未配置的模型名，可以设置一条默认路由，使这些调用回退到该路由；调用详情会将这类调用标记为兜底解析。

## 签发 Agent 密钥

在项目的“Agent 密钥”页面签发密钥。完整密钥只显示一次，请在签发时复制。密钥带有标签、可选的请求速率与并发限额，以及策略规则会用到的角色和信任级别。只有管理员可以设置非默认角色或信任级别。

## 将 Agent 接入网关

将网关地址和密钥提供给 Agent，模型名使用路由名称。上游模型名保留在目录中，不会暴露给客户端。

| Agent 协议         | 基础地址                   | 密钥位置                            |
| ------------------ | -------------------------- | ----------------------------------- |
| Chat Completions   | `http://127.0.0.1:8080/v1` | `Authorization: Bearer <key>`       |
| Responses          | `http://127.0.0.1:8080/v1` | `Authorization: Bearer <key>`       |
| Anthropic Messages | `http://127.0.0.1:8080`    | `x-api-key: <key>`                  |
| Gemini             | `http://127.0.0.1:8080`    | `x-goog-api-key: <key>`，或 `?key=` |

多数客户端都支持自定义基础地址，因此 Claude Code、Codex、Gemini CLI 或普通 HTTP 客户端都能接入同一个入口。可选的 `X-SafeAgent-Session` 请求头将同一 Agent 密钥下的调用归入同一条轨迹，身份仍然来自密钥。客户端支持时应优先使用 `previous_response_id`。

发起第一个请求：

```sh
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer <agent-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"public-model","messages":[{"role":"user","content":"hello"}]}'
```

## 使用控制台

请求将出现在项目的“调用”页面。每行带有通道、操作、用途和结果标记，主调用、后台调用和辅助协议调用可以直接区分。辅助调用默认隐藏，开启后才显示；侧调用可以按通道折叠。

打开一条轨迹即可查看状态、覆盖度、调用、发现和事件时间线。覆盖度显示已观察与期望边界以及采集缺口；时间线就是审计日志本身。调用详情展示尝试、发现和事件，并可返回所属轨迹。轨迹页列出脱敏值，但不会展示原值。

项目的“轨迹”页面列出各项被委派任务及其覆盖度、风险与发现数量；轨迹详情展示状态、调用、发现、内容片段、事件时间线和完整性。监控页给出跨项目的流量、失败和近期高危调用。策略与脱敏页面分别维护有序规则表和检测规则，保存时校验并立即生效。

如需端到端确认脱敏效果，可发送一段包含邮箱地址的提示词。上游收到的请求中包含 `[EMAIL_…]` 这样的占位符，客户端收到的回复中包含原始邮箱，而这次调用会显示一个脱敏值。

## 容器部署

构建镜像并挂载配置：

```sh
docker build -t safeagent .
docker run -d --name safeagent -p 127.0.0.1:8080:8080 \
  -v "$PWD/config.toml:/app/config.toml:ro" safeagent
```

在容器中，服务需要监听所有网卡，数据库地址也要能从容器内解析：

```toml
listen = "0.0.0.0:8080"
database_url = "postgres://safeagent:change-me@db-host:5432/safeagent?sslmode=require"
instance_key = "<openssl rand -base64 32 的输出>"
secure_cookies = true
```

启用 `secure_cookies = true` 后，控制台需要 HTTPS。应通过终止 TLS 的反向代理对外提供服务，并将 `public_origin` 设为浏览器实际访问的地址，例如 `https://safeagent.example.com`。如果反向代理直接连接应用，将代理的地址或 CIDR 加入 `trusted_proxies`，控制台才能获取客户端地址用于登录限流。请从容器外部检查 `/health`。

## 故障排查

| 提示或现象                           | 处理方式                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------------ |
| `database_url is required`           | 在配置文件中填写该项，或确认进程读取的是已编辑的文件。                                     |
| `instance_key is required`           | 填写 32 字节 base64 的 `instance_key`。                                                    |
| 启动时报未知配置键                   | 某个键拼写有误，按错误信息中的名称改正。                                                   |
| 控制台返回 404                       | 控制台前端尚未构建，运行 `make build`。                                                    |
| 登录成功但刷新后被登出               | 部署在 HTTP 下却设置了 `secure_cookies = true`。使用 HTTPS，或在回环地址上将其设为 false。 |
| 反向代理后控制台写操作失败           | 将 `public_origin` 设为用户在浏览器中打开的地址。                                          |
| 控制台中供应商或模型出现告警         | 某条路由引用了已删除或已停用的对象。恢复对象，或移除受影响的目标。                         |
| 请求返回 403，或流以工具调用错误结束 | 命中了阻断类脱敏规则、策略规则或决策模型的否决。调用记录会写明来源，轨迹与证据仍会记录。   |
| 后台调用成功但轨迹列表不显示         | 侧调用与辅助调用按设计折叠或隐藏，打开对应的通道筛选即可。                                 |
