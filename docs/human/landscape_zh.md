# 同类方案

[English](landscape.md)

AxonHub、magpie 与 Sub2API 各自在 Agent 和模型服务之间放了一个网关，但优化的目标不同：供应商覆盖、本机 Agent 配置，以及订阅配额。把 SafeAgent 放在它们旁边，更容易说清它是什么，以及它刻意不做什么。

## 比较方法

这里的比较是定性的，依据三个项目公开的文档与 README，没有运行基准测试；它描述各家大体的做法，不涉及某个具体版本的细节。它们是相邻方向上的设计，不构成排名。功能、许可证和内部实现都变化很快，需要依赖某个细节时请直接查项目本身。

## SafeAgent

SafeAgent 是面向 Agent 行为的自托管安全网关。它接住 Chat Completions、Responses、Anthropic Messages 与 Gemini，经由一套规范模型双向转换，对两个方向上的敏感值脱敏，并把每次准入的调用写入签名审计链。

分析单位是一次调用，调用链组成会话。控制面把全局供给图（供应商、渠道、模型）与项目路由策略（路由、目标、别名）分开。存储使用 PostgreSQL，schema 只有一份基线，事件以 HMAC 串联。网关、控制台与诊断进程由同一个 Go 进程提供。

## AxonHub

AxonHub 是多供应商 AI 网关与开发平台：用一套接口接入大量模型，并提供路由、负载均衡、成本统计、RBAC 和请求追踪。它的供应商目录很大，包含各种厂商变体和 OAuth 渠道。

分析单位是 trace 或 thread，分为请求层与执行层。控制面把渠道、模型与关联规则拆开，一个模型可以接到多个渠道，路由策略单独编辑。请求经过一层以 OpenAI Chat Completions 为形状的统一中间表示，非 OpenAI 语义放在附加字段里；同格式流量可以按原始字节透传。它的关系型 schema 由 ORM 管理并采用软删除，管理操作有专门的后台界面。

## magpie

magpie 是面向多个 Agent CLI 的本机网关与配置协调器。它给 Claude Code、Codex 这类工具一个统一地址，归集上游账号，并替它们写出客户端配置。

分析单位是一次网关调用，按客户端会话分组。控制面围绕供应商、账号、组和路由组织。协议转换覆盖四种格式，改写 Agent 配置文件是它的核心能力。它按客户端声明的类型、归一化后的用途以及调用方是 Agent 还是网关自身来区分调用；脱敏值会得到确定性占位符，并以此作为值的身份。状态保存在本地文件中，不放进共享数据库。

## Sub2API

Sub2API 是订阅配额分发与转售平台。它归集上游账号，并按用户、组和模型管理配额、计费、限流与调度。

分析单位是单次请求，用量与运营错误分两本账记录。控制面围绕账号、组、渠道与组合组组织。协议转换以成对转换为主，部分路径把 Responses 当作枢纽。持久状态存放在关系型数据库中，旁边另有一层缓存。

## 对照

| 维度     | SafeAgent                                        | AxonHub                            | magpie                            | Sub2API                    |
| -------- | ------------------------------------------------ | ---------------------------------- | --------------------------------- | -------------------------- |
| 定位     | Agent 行为安全网关                               | 多供应商 AI 网关与平台             | 本机多 Agent CLI 网关与配置协调器 | 订阅配额、计费与中转       |
| 分析单位 | 一次调用，调用链组成会话                         | trace 或 thread，分请求层与执行层  | 一次网关调用，按客户端会话分组    | 单次请求，用量与错误分账   |
| 控制面   | 供应商 → 渠道 → 模型的供给图，加上项目路由与别名 | 渠道与模型，加上关联规则           | 供应商、账号、组与路由            | 账号、组、渠道与组合组     |
| 协议策略 | 四格式规范模型，同格式原始透传                   | 统一 OpenAI 形状中间表示，成对转换 | 四格式互转，改写 Agent 配置       | 成对转换，Responses 作枢纽 |
| 存储     | PostgreSQL，单一 schema 基线，签名审计链         | 关系型 schema，由 ORM 管理         | 本地文件                          | 关系型数据库加缓存层       |

## SafeAgent 借鉴了什么

- **来自 AxonHub**：供给配置与路由策略分层，可见的请求与尝试链路，以及从类型化节点重建轨迹并支持多种视图的做法。OpenAI 形状的中间表示与面向具体客户端的处理仍是 AxonHub 的选择。
- **来自 magpie**：按端点操作、声明用途与通道对调用分类；把确定性占位符当作值的身份，使重复出现的同一脱敏值合并成一条。
- **来自 Sub2API**：带影响检查的软删除生命周期，以及把用量账与错误账分开记录的习惯。

这些做法的组合才是 SafeAgent 的取舍：转换、在线策略与审计放在同一条调用路径上，供应商范围比通用网关窄，策略落在工具边界，而不只是事后检查流量。
